## 1. 论题与命名

### 1.1 论题 (Thesis)

据实是一本**不发表意见的账本**。它从不说「你花太多了」，它只说「今日可用 −¥84.20」，然后让这个数字待在那里。它的反乱花钱机制不是提醒、不是奖励、不是评级弹窗，而是**对照你自己划下的标准做诚实记账**：每一笔支出在花钱的当下被盖上 `必要 / 想要 / 冲动` 三枚印章之一（强制、无默认值）；每一笔 `想要` 和 `冲动` 会在周日回来，由你自己给出 `值 / 不值` 的二元判决；判为不值的金额累进成一个**本年后悔**数字——永不清零、永不软化、月度结账后永不可静默修改。尚未发生的购买进入待购清单，按价格比例冷静；因此本应用唯一主动施加的摩擦，被放置在钱离开之前，而不是之后。设计人格是彻底的克制——纸张、墨、发丝线、等宽数字——因为一个你无法反驳的数字，比任何警告横幅都更有矫正力。

### 1.2 命名规则

| 场景 | 用名 | 说明 |
|---|---|---|
| 中文主名 | **据实** | 全部中文界面、App Store 中国区名称、文案中的自称 |
| 英文主名 | **Countbook** | 英文界面、仓库名、包名、域名、技术文档 |
| 组合式署名 | `据实 Countbook` | 网页 `<title>`、关于页、导出文件头 |
| 一句话副标 | 中：`记账，不评判` · 英：`A ledger that does not editorialise.` | App Store 副标题、PWA `description` |
| 已弃用 | ~~花得值~~ | **不得使用**。它承诺了一个判断，而本应用的立场是判断由用户自己下 |
| Bundle ID / 包名 | `com.countbook.jushi` | iOS |
| Web 根路径 | `/countbook/` (GitHub Pages) | 需支持自定义域名下的 `/` |

- 中文界面中，功能名一律使用中文（今日、账页、报告、待购、订阅、设置），**不得**出现中英并置（如「今日 Today」）。英文界面为独立字符串表，不是括注。
- 语气规范（全局，见 §7.6）：陈述句、无感叹号、无表情、无第二人称祈使、无「太棒了 / 加油 / 继续保持」。文案人格是**一名不加评论的记账员**。

## 2. 功能清单与验收标准

功能编号 `F-x`，验收标准编号 `AC-x.y`。所有 AC 必须可由评审者在真机/浏览器上手工核验，或由单元测试断言。

### 2.A 记录 (Capture & Ledger)

**F-1 快速记账 (记一笔)** — 详见 §4。
- AC-1.1 从任意主屏点击 `记` 到记账面板可交互 ≤ 200ms（无加载态、无骨架屏）。
- AC-1.2 一笔完整记录（金额 3 位 + 类别 + 印章 + 保存）恰好 6 次点击，可由自动化脚本计数验证。
- AC-1.3 金额为 0 时保存按钮不可用；印章未选时保存按钮不可用且呈 `--ink-300`，非交互（不是变灰但仍可点）。
- AC-1.4 `entry.intent` 在数据库中为 NOT NULL 且无 DEFAULT；任何绕过 UI 的写入路径（导入、同步）若缺失 intent，该记录被拒收并写入 `import_rejects`。
- AC-1.5 保存后无 toast、无「已保存」、无音效、无成功色；仅发生 §4.9 描述的两处动效。
- AC-1.6 长按 `存入账页` ≥ 400ms 保存并保留面板（金额清零，类别与印章保留，日期保留）。
- AC-1.7 离线（飞行模式/断网）下全流程可用，无任何网络请求发出（可用浏览器网络面板与 iOS Charles 核验为 0 请求）。

**F-2 账页 (Ledger)**
- AC-2.1 按日分节，节头为 `03-14 · 周五 · ¥312.00`（等宽）。
- AC-2.2 行内元素顺序固定：等宽时间(ink-300) · 类别(ink-700) · 备注(ink-500，单行截断) · 印章字(必/想/冲, ink-300) · 金额（右对齐进 96pt 槽）。
- AC-2.3 搜索对备注、类别名、商户名做子串匹配（大小写与全半角不敏感），200 条以内结果 ≤ 50ms 返回。
- AC-2.4 筛选态以下划线词呈现，非胶囊、非填充色。
- AC-2.5 滚动 5,000 条记录时帧率 ≥ 50fps（虚拟列表，中端 Android Chrome / iPhone 12）。

**F-3 结账与更正 (Period close, 更正/冲销)** — 详见 §5.10。
- AC-3.1 已结账周期内的记录，直接编辑入口不存在；点击行进入的是「更正」表单。
- AC-3.2 提交一次更正所需操作 ≤ 2 次点击 + 输入事由（最少 2 字符），事由为空时提交按钮不可用。
- AC-3.3 更正后原行仍在，其下方新增一行等宽 ink-500：`更正 · 原 ¥288.00 → ¥88.00 · 事由：录错`。
- AC-3.4 删除已结账记录不会移除任何行，而是追加 `冲销` 行；所有聚合按更正后金额重算，但更正行永久可见。
- AC-3.5 当前（未结账）周期内的编辑与删除是静默的、不留痕的；删除提供 8 秒 `撤销`。

**F-4 零支出打卡 (今天没花钱)**
- AC-4.1 今日无任何记录时，今日屏出现一条发丝线行 `今天没花钱`，点击写入 `ZeroDayMark`。
- AC-4.2 未记录且未打卡的日子在报告中计为 `未记录`，**不**计入达标天数、不计入完整度分子。
- AC-4.3 已打卡日再新增记录时，`ZeroDayMark` 自动作废（追加 `zero_day_void` 事件，不静默删除）。

### 2.B 前置摩擦 (Pre-spend friction)

**F-5 待购冷静期** — 公式见 §5.4。
- AC-5.1 待购项写入即计算 `unlockAt`，冷静期天数 = `clamp(ceil(price_fen / 10000), 1, 14)`，边界值 ¥100.00→1、¥100.01→2、¥3000.00→14、¥99999→14 必须单测通过。
- AC-5.2 `now < unlockAt` 时 `已买` 不可用；行显示 1px 递减弧（`--fig-held`）与等宽倒计时 `还有 6 天 04:12`。
- AC-5.3 弧每 60 秒重绘一次；不得使用 `requestAnimationFrame` 循环或 `TimelineView(.animation)`（代码评审项）。
- AC-5.4 解锁后该项浮到列表顶部，只出现一个问题 `仍然想要吗？` 与两个动作 `记入账页` / `不买了`。
- AC-5.5 `不买了` 写入 `AbstainedWant`，其价格计入本年 `已放弃`（`--fig-spared`）。
- AC-5.6 iOS 在 `unlockAt` 投递本地通知；Web 不投递通知，改为下次打开时的置顶行（见 §5.4.4 与 §11 风险）。

**F-6 挂起替代 (capture 内的冷静路径)**
- AC-6.1 当 `intent ∈ {想要, 冲动}` 且 `amount ≥ coolingThreshold`（默认 ¥300）时，主按钮文案与语义变为 `挂起 N 天`（`--fig-held`），`仍要立即记入` 降级为按钮下方的纯文本链接。
- AC-6.2 点击 `挂起 N 天` 创建待购项而非记账，金额不进入账页。
- AC-6.3 `仍要立即记入` 需 3.0 秒线性长按（F-7）并要求填写 ≤20 字事由（§4.7）。

**F-7 三秒长按环**
- AC-7.1 触发条件（满足任一）：(a) `intent == 冲动` 且 `amount ≥ ¥200`；(b) 保存后 `今日可用` 将 < 0 且 `amount ≥ ¥50`；(c) 走 `仍要立即记入` 路径。
- AC-7.2 环为 1px 未填充描边，**线性**填充，无缓动，3000ms，提前松手即取消且无任何提示文案。
- AC-7.3 `prefers-reduced-motion` / `accessibilityReduceMotion` 下环不动，改为等宽倒计时 `3 · 2 · 1`，时长不变。

### 2.C 回顾判决 (Retrospective judgement)

**F-8 周日审判**
- AC-8.1 触发时间默认 `周日 20:00`（星期与小时可配）；到时后今日屏出现发丝线行 `本周 11 笔待判`。
- AC-8.2 卡组最多 12 张，按金额降序；每张显示 44px 金额、类别、备注、事由（若有，用引号原文回引）、日期、`已过 N 天`。
- AC-8.3 动作三选一：`值` / `不值` / `稍后`。`稍后` 每笔最多 3 次。
- AC-8.4 第 4 次出现时自动记为 `不值`，`autoJudged=true`，事由固定 `未敢面对`；报告中单列 `其中未敢面对 ¥N`。
- AC-8.5 整个流程可跳过（`跳过` 纯文本链接），跳过不产生任何提示或再次弹出。
- AC-8.6 结束页只有一行：`本周 11 笔待判 · 3 笔不值 · ¥612`，无祝贺、无动画庆祝，2 秒后仍需手动关闭。

**F-9 后悔账**
- AC-9.1 `本月后悔` 与 `本年后悔` 只出现在报告页页首，**今日屏、账页、待购、订阅任何位置均不得出现**（评审项）。
- AC-9.2 二者以 `--fig-regret`（冷铅灰）呈现，不使用 `--fig-over` 红。
- AC-9.3 `本年后悔` 按自然年累计，跨月、跨周期永不清零，且不显示任何「同比/好于去年」的对比句。
- AC-9.4 后悔率与后悔率方块图在全局已判笔数 < 30 时**不渲染**，改印 `已判 12 笔 · 满 30 笔后给出后悔率`。

**F-10 心愿物换算**
- AC-10.1 最多 3 个心愿物（名称 ≤ 12 字 + 价格）。
- AC-10.2 `本年后悔` 下方一行 13px：`已经买得起「换相机」的 23%`，其下 1px 进度尺。
- AC-10.3 比例 ≥ 100% 时文案改为 `已经够买 1.4 个「换相机」`，进度尺满格不溢出。
- AC-10.4 未设置心愿物时该行不存在（不显示占位、不诱导设置）。

### 2.D 使不可见者可见 (Making leaks visible)

**F-11 小额漏水**
- AC-11.1 今日屏一条发丝线条带：`本月 47 笔小额 · ¥1,238 · ≈ 3.1 次大额支出`。
- AC-11.2 等价除数 = 近 90 天中 `amount ≥ leakCeiling` 记录的中位数；该类样本 < 10 笔时省略 `≈` 从句，只印 `本月 47 笔小额 · ¥1,238`。
- AC-11.3 点击进入账页且预置该筛选，默认按 商户/备注 归一化字符串的**频次**降序。
- AC-11.4 报告页给出商户维度重述：`便利店 ×14 · ¥382 · 近 30 天 · ≈ 2.6 次大额支出`。

**F-12 订阅与年化**
- AC-12.1 订阅页页首一个数字：`年化 ¥4,296 · 每天 ¥11.77`（34px）。
- AC-12.2 行按**年化金额降序**排列（不是名称、不是日期、不是新旧）。
- AC-12.3 行内容：`月付 ¥25 · 年化 ¥300` / `已付 ¥1,140（自 2022-01）` / `下次 03-14`；已付若为推算，其后附 ink-300 等宽 `估算`。
- AC-12.4 记录使用后显示 `每次使用 ¥37.5`（近 90 天口径，使用次数 < 3 时不显示）。
- AC-12.5 标记取消后行移入 `已终止`，并累计 `已省 ¥2,180`（`--fig-spared`），该数字持续增长，永不清零。

**F-13 周期性扣费探测（待认领）**
- AC-13.1 探测为纯本地逻辑，规则见 §5.6；命中项进入 `待认领` 区，默认状态为**未认领**。
- AC-13.2 应用**不得**自行把探测结果当作订阅计入年化；只有用户逐行签署 `保留` 或 `待退订` 后才生效。
- AC-13.3 `餐饮` 类别命中阈值提高到 ≥5 次（抑制每周工作餐误报）。
- AC-13.4 用户对某分组选择 `不是订阅` 后，该 `merchantKey + amountBucket` 组合 180 天内不再提示。

**F-14 时段散点（深夜下单）**
- AC-14.1 报告页 24 列散点，仅统计近 90 天 `想要 + 冲动` 记录。
- AC-14.2 头行文案：`23:00–02:00 共 31 笔 · ¥2,140 · 占非必要支出 38%`。
- AC-14.3 样本 < 20 笔时不渲染图，改印 `非必要记录 12 笔 · 满 20 笔后给出时段分布`。

### 2.E 标准与报告

**F-15 标准线与标准修订**
- AC-15.1 首次运行必须设置 `月度标准`（总额）方可进入主界面；分类标准可选。
- AC-15.2 数据满 30 天后，应用在每个标准字段旁以 ink-300 显示近 90 天中位数建议；建议**必须显式点击接受**，不得自动填入。
- AC-15.3 任何标准、阈值（冷静期起点、漏水上限、审判日、日切、结算起始日）的修改都写入一条带日期的 `StandardRevision`，不可编辑、不可删除。
- AC-15.4 报告页页脚永久列出本年所有标准修订：`2026-04-01 · 月度标准 ¥8,000 → ¥9,500`。

**F-16 报告 / 对账** — 统计口径见 §7。
- AC-16.1 所有分类图表以**对标准的偏差**呈现，不出现绝对总额条形图。
- AC-16.2 分类表按 `后悔金额` 降序排列（不是笔数、不是后悔率）。
- AC-16.3 `导出本页`：Web 触发打印样式表（`window.print()`）；iOS 用 `ImageRenderer` 输出 PDF + PNG。二者版式与屏幕一致。
- AC-16.4 月度评级 A–E 与其完整公式在设置页原文可见（§5.9）。

**F-17 破版 (Margin break)**
- AC-17.1 当日实际支出 > 当日额度时，今日屏英雄数字下方的规则线与月度日柱的基线向右越出 720px 内容列 20px，仅被安全区裁切。
- AC-17.2 该效果不引入第四种颜色，不引入阴影，不引入图标。
- AC-17.3 Web 用负 margin，iOS 用负水平 padding；两端越界像素数一致（±1px 截图比对）。

### 2.F 多端与数据

**F-18 多端登录与同步** — 协议见 §8.5。
- AC-18.1 同步默认**关闭**；关闭时应用零网络请求。
- AC-18.2 账本以 `账本 ID + 口令` 登录；同一账本在第二台设备登录后，两端在联网 10 秒内收敛到同一账页。
- AC-18.3 密钥指纹以四组十六进制等宽显示：`4F2A · 91C7 · 0B3E · D845`，两端必须一致。
- AC-18.4 同步状态是一个词：`已同步` / `待同步`（`--fig-held`）/ `离线`；**任何位置不得出现旋转指示器**。
- AC-18.5 服务器仅存储不透明密文块；用服务端日志核验：请求体中不含任何明文金额、类别、备注。
- AC-18.6 断网 7 天后重连，事件按 HLC 归并且不产生重复行（构造 300 事件冲突用例断言）。

**F-19 导出 / 导入** — 格式见 §8.6。
- AC-19.1 CSV 导出为 UTF-8 **带 BOM**，Excel / WPS 中文不乱码，金额列为元（两位小数字符串），另有分列。
- AC-19.2 JSON 导出为完整 bundle，含 `schemaVersion`，可被本应用完整导入还原（往返测试：导出→清库→导入→逐字段等价）。
- AC-19.3 导入为**合并**语义（按事件 id 去重），不是覆盖；导入前显示将新增/跳过的条数并需确认。

**F-20 PWA / 离线**
- AC-20.1 首屏静态资源全部同源，构建产物中不含任何 `http(s)://` 外链（构建期 grep 断言，字体、脚本、图片皆无）。
- AC-20.2 断网冷启动可完整使用全部功能。
- AC-20.3 可安装（`manifest.webmanifest` + 512/192 图标 + `display: standalone`）。
- AC-20.4 JS 首屏包 ≤ 180KB gzip，CSS ≤ 40KB gzip。

## 3. 屏幕清单与导航模型

### 3.0 五个顶层目的地（两端一致）

| # | 中文 | 英文 | 路由 (web) | 说明 |
|---|---|---|---|---|
| 1 | 今日 | Today | `/today` | 站立数字与今日流水 |
| 2 | 账页 | Ledger | `/ledger` | 永久记录 |
| 3 | 计划 | Plans | `/plans` | 分段：`待购` / `订阅` |
| 4 | 报告 | Report | `/report` | 对账与判决产出 |
| 5 | 设置 | Settings | `/settings` | 标准、阈值、设备、数据 |

**决定：** 待购与订阅合并为一个顶层目的地「计划」，用两段分段控件切换（`待购 · 订阅`）。理由：两者都是「尚未发生或反复发生的承诺」，都属于钱离开之前的管理；五个底部标签是移动端的上限，把它们并为一个避免了六标签或把订阅埋进设置。

### 3.1 iOS 导航模型

- 根为 `TabView`，5 个标签，标签为**纯文字**（无 SF Symbol 图标）；选中态为 `--ink-900` + 上方 2px 墨线，未选中为 `--ink-500`。（决定：iOS 惯例的图标标签在此被放弃，因为整套设计语言禁止图标；文字标签在 iOS 上完全合法。）
- 每个标签内为 `NavigationStack`，支持系统边缘返回手势。
- 记账面板：`.sheet`，自定义 detent `.fraction(0.92)`，不可下拉到中间态（只有全开与关闭），带抓手条 `--rule-strong`。
- 周日审判：`.fullScreenCover`。
- 更正表单、心愿物编辑、订阅编辑：`.sheet` `.fraction(0.55)`。
- `记` 按钮：56pt `--ink-900` 圆形，字符「记」，出现在 `今日` 与 `账页`，位于右下，距安全区 20pt。
- 触觉：印章选中 `.impact(.light)`；保存成功 `.impact(.soft)`；长按环完成 `.impact(.rigid)`。判决卡滑动无触觉。（决定：触觉是 iOS 惯例且不违反视觉克制；Web 无对应，允许差异。）
- 深层链接：`countbook://capture`（Shortcuts/URL scheme）直接打开记账面板。

### 3.2 Web 导航模型

- 路由：`BrowserRouter`，base `/countbook/`；GitHub Pages 部署时复制 `index.html` 为 `404.html` 以支持深链回落。
- **视口 ≥ 900px**：左侧固定导轨（宽 200px），5 个目的地竖排为文字列表，选中态为左侧 2px 墨线；内容列 720px 居中于 `--paper`。

## 4. 记一笔：逐次点击的完整流程

**这是全应用最重要的流程。中位完成时间目标 ≤ 6 秒、6 次点击。任何会使其变慢的改动一律拒绝（§9 非目标 N-1）。**

### 4.1 面板结构（自上而下，固定顺序）

```
[ 日期片 03-14 周五 ]                      [ 关闭 ]     ← 32px 行
                                    ¥ 1 2 8 . 0 0      ← 44px 金额显示，右对齐

   1      2      3                                      ← 键盘 3×4
   4      5      6
```

### 4.2 打开

- 入口：今日/账页右下 `记` 按钮、Web 快捷键 `N`、iOS URL scheme。
- 打开时初始状态：金额 `0`、类别未选、印章未选、日期 = 记账日（按日切规则，§4.6）、备注空。
- 键盘立即可用；**不自动聚焦备注输入框**（避免弹出系统键盘遮挡）。
- 面板打开动效：`translateY 24→0` + `opacity 0→1`，280ms，`--ease`；遮罩 `0→0.28` 200ms 线性。

### 4.3 数字键盘行为（精确规范）

内部状态：`intPart: string`（≤ 6 位）、`fracPart: string`（≤ 2 位）、`inFrac: bool`。

| 按键 | 行为 |
|---|---|
| `0–9` | `inFrac == false`：若 `intPart == "0"` 则替换，否则追加；`intPart.length == 6` 时忽略（无抖动、无提示）。`inFrac == true`：追加到 `fracPart`；`fracPart.length == 2` 时忽略。 |
| `.` | `inFrac = true`。已在小数态时为空操作。`intPart == "0"` 时保留 `0`，显示 `¥0.` |
| `⌫` 短按 | `inFrac && fracPart.length > 0` → 删 `fracPart` 末位；`inFrac && fracPart 空` → `inFrac = false`；否则删 `intPart` 末位，删空则回到 `"0"` |
| `⌫` 长按 ≥ 400ms | 全部清零，回到 `¥0`，`inFrac = false` |

- 显示规则：整数部分每 3 位插入千分位逗号；小数部分按 §附录 B 的三段式排版（`¥` 0.44×，元 1.0×，分 0.56×）。未进入小数态时显示 `¥1,280`（不补 `.00`）；进入小数态显示 `¥1,280.` → `¥1,280.5` → `¥1,280.50`。
- 保存时的取值：`amountFen = intPart * 100 + pad_right(fracPart, 2, '0')`。`¥1,280.5` 保存为 `128050`。**全流程整数分，禁止出现浮点。**
- 上限：`99,999,999` 分（¥999,999.99）。
- 键盘按键无涟漪、无缩放动效；按下态仅为背景切到 `--surface-sunken`，抬起即恢复（80ms opacity）。
- Web 桌面：物理键盘 `0-9`、`.`、`Backspace`、`Enter`（保存）、`Esc`（关闭）等价映射。

### 4.4 类别选择

- 固定 3×4 = 12 格，**纯文字，无图标、无颜色**。
- 选中态：1px `--ink-900` 方框（radius 0），文字变 `--ink-900` weight 500。未选：`--ink-700` weight 400，无边框。
- 一次点击选中；再次点击同一格**不取消**（避免误触导致无类别）。切换即改选。
- 顺序：默认按 §6.1 的固定顺序。每月 1 日按上一个自然月的使用频次重排一次（频次相同按默认顺序），此后当月内**顺序冻结**，以保护肌肉记忆。设置中提供 `固定顺序` 开关（默认关，即允许月度重排）。
- 长按某格 → 该类别的分类标准编辑（快捷入口，不阻塞记账）。

### 4.5 印章（必要 / 想要 / 冲动）

- **强制、无默认值、无推断。** 未选时 `存入账页` 为 `--ink-300` 且 `pointer-events: none` / `.disabled(true)`。
- 视觉：三个词等宽三分，未选与已选的文字颜色相同（`--ink-700`）；唯一的选中指示是词下方一条 2px `--ink-900` 横线，用 180ms `--ease` 从上一位置滑到新位置（Web `transform: translateX`，SwiftUI `matchedGeometryEffect`）。**无填充、无胶囊背景、无颜色。**
- 首次选择时无滑动起点，则线以 `scaleX 0→1` 从该词左端画出，180ms。
- 语义定义（设置页原文可见，且首次运行时展示一次）：
  - `必要`：不买会产生实际损失或无法履行义务。
  - `想要`：计划中的、当时就知道自己在选择的花费。
  - `冲动`：五分钟前还没打算买。
- 选中印章后若满足 §5.4 条件，主按钮文案立即变为 `挂起 N 天`（`--fig-held`），并在其下出现纯文本链接 `仍要立即记入`。

### 4.6 日期处理

- 记账日 = 按 **日切**（`dayCutoffHour`，默认 `00:00`，可选 `02:00` / `04:00`）折算的本地自然日。`04:00` 日切时，3 月 15 日 01:30 的记录归入 `03-14`。
- 面板左上日期片显示 `03-14 周五`（等宽）。点击展开一行快捷：`今天 · 昨天 · 前天 · 选择日期…`。
- `选择日期…` 打开系统日期选择器（iOS `DatePicker` graphical / Web `<input type="date">`，两端均为本地组件，零依赖）。
- **不可选未来日期**（超过记账日的日期不可点）。理由：账本记录已发生的事；未来的花费属于待购或订阅。
- 补录（非记账日）时：`entry.ts` 仍为真实写入时刻，`entry.occurredOn` 为所选日；账页时间列显示 `12:00` 并附等宽 ink-300 标记 `补`。
- 若所选日期属于**已结账周期**：面板顶部出现一行 ink-500 `该月已结账，将记为更正`，且备注下方多出必填事由字段（≥2 字），保存后按 §5.10 追加行。

### 4.7 备注与「写给未来的自己」

- **备注**：单行，≤ 40 字，永远可选、永不阻塞。占位符 `备注（可选）`。
- **事由（写给未来的自己）**：≤ 20 字，占位符 `一句话，写给三天后的自己`。出现规则：
  - `intent == 想要` 且 `amount ≥ coolingThreshold` → **出现且可选**。
  - 走 `仍要立即记入` 路径（即覆盖了冷静期建议）→ **出现且必填**，标题为 `这笔钱能换来什么？`，不填则该路径不可提交。
  - 其他情况 → 不出现。
- 事由文本在周日审判卡片上以中文直角引号原文回引：`「换来一个能安静写代码的下午」`。

### 4.8 保存按钮的三种形态

| 条件 | 按钮 | 附属 |
|---|---|---|
| 常规 | `存入账页`（ink-900 实底，白字） | — |
| `intent ∈ {想要,冲动}` 且 `amount ≥ coolingThreshold` | `挂起 N 天`（`--fig-held` 描边 + 同色字，非实底） | 下方链接 `仍要立即记入` |
| 该类别 `后悔率 > 40%` 且 `amount > 该类别近 90 天中位数` 且 样本达标（全局已判 ≥30 且该类别已判 ≥8） | `存入账页 · 这类你 62% 判过不值` | 文案不换行则字号降到 15px；**不弹窗、不阻塞、不变色** |

- 第 2 与第 3 种可同时命中：此时主按钮为 `挂起 N 天`，第 3 种文案挂在 `仍要立即记入` 链接后：`仍要立即记入 · 这类你 62% 判过不值`。
- 长按 `存入账页` ≥400ms：保存并保留面板（AC-1.6）。长按不与 F-7 的 3 秒环冲突——当 3 秒环生效时，长按即为环本身，`保存并保留` 功能在该情形下不可用。

### 4.9 保存时发生什么（签名瞬间）

按下 `存入账页`（或长按环填满）后，严格按此时序，**总时长 400ms 内**：

| t (ms) | 事件 |
|---|---|
| 0 | 写入事件日志（同步、本地、无 await 网络）；聚合同步重算 |
| 0 | 面板开始下移 24px + 淡出，200ms `--ease`；遮罩 200ms 线性淡出 |
| 0 | 账页中新行位置的发丝线以 `scaleX 0→1`（`transform-origin: left`）画出，240ms |
| 0 | 英雄数字 `今日可用` 逐位 settle：仅发生变化的数字位上移 6px + 交叉淡入，220ms，自右向左错开 18ms |
| 160 | 新行内容开始淡入，120ms |
| 280 | 全部结束 |

- **不出现**：toast、「已保存」、勾选动画、音效、任何绿色、任何弹跳/回弹/过冲。
- 若 `今日可用` 跨越 0 变负：数字直接以 `--fig-over` 出现，同时该行下方规则线破版右越 20px。**无其他任何提示。**
- `prefers-reduced-motion` / `accessibilityReduceMotion`：以上全部塌缩为 100ms opacity 变化。
- 记账后**不返回列表顶部、不滚动、不高亮新行**（除画线本身）。

### 4.10 失败与边界

- 金额为 0 或印章为空 → 按钮不可用（不弹错误）。
- 存储写入失败（IndexedDB 配额、iOS 磁盘满）→ 面板不关闭，按钮下方出现一行 `--fig-over` 13px：`未能写入本地存储 · 请清理空间后重试`。这是全应用**唯一**允许用 `--fig-over` 表达错误的位置（见 §11 R-6 的处置）。
- 应用在面板打开时被杀死：草稿（金额/类别/印章/备注/日期）持久化到本地，下次打开 `记` 时恢复，顶部一行 ink-500 `恢复了未完成的一笔`，可一键 `丢弃`。

## 5. 反乱花钱机制（公式与规则）

所有金额为 `Int64` 分。除法一律说明取整方向。`floorDiv(a,b)` 表示向负无穷取整。

### 5.1 周期定义

- `periodStartDay ∈ [1,28]`，默认 `1`（自然月）。周期 = `[periodStartDay 当月, 下个 periodStartDay − 1 天]`。
- `today` = 按 `dayCutoffHour` 折算的记账日。
- `D` = 从 `today` 到周期末（含今天）的天数。
- 自然年（用于 `本年后悔`、`本年已放弃`）始终为公历 1 月 1 日起，不随 `periodStartDay` 变化。

### 5.2 今日可用 (Safe-to-spend) — 英雄数字

```
S            = standardFen                                  // 月度标准（总额）
spentBefore  = Σ effective(e) for e where periodStart ≤ e.occurredOn < today
                 and e.amortized == false and e.voided == false
spentToday   = Σ effective(e) for e where e.occurredOn == today
                 and e.amortized == false and e.voided == false
amortPool    = Σ effective(e) for e where e.occurredOn in period and e.amortized == true
fixedRemain  = Σ 订阅预计扣费(charge.date ∈ (today, periodEnd])
                 + Σ 手动固定支出(due ∈ (today, periodEnd])

dailyAllowance = floorDiv(S − amortPool − fixedRemain − spentBefore, D)
todayAvailable = dailyAllowance − spentToday
```

- `effective(e)` = 该记录经所有 `更正` 后的最终金额；被 `冲销` 的记录 `effective = 0`。
- **模型说明（必须按此实现）**：今天花的钱**全额**从今日数字里扣（所以一笔 ¥68 让 ¥126.40 变成 ¥58.40）；今天的超支在明天被摊到剩余天数里（所以一顿 ¥400 的饭在明天体现为「每天少 ¥28」）。这同时满足签名瞬间与「日均后果」两个诉求。
- 周期最后一天 `D == 1`，`dailyAllowance` 自动吃掉全部余数——**无需单独的余数逻辑**，向下取整产生的余数自然累积到最后一天。
- `todayAvailable` 是全应用**唯一**允许为负、也是唯一使用 `--fig-over` 的数字（另一个用处见 5.3 分类超标条）。
- 大额必要摊销：保存 `intent == 必要` 且 `amount ≥ amortizeThreshold`（默认 ¥800）时，保存后账页该行右侧出现一次性文本链接 `摊入本月固定`（存在 24 小时）。点击后 `amortized = true`，该笔从 `spentBefore/Today` 移入 `amortPool`，即由「今天一次性打击」变为「摊薄到剩余每一天」。**总额不变**，仅改变分布；该操作写入事件日志并在报告页脚以 `摊销 · 03-14 · 医疗 ¥2,400` 列出。仅 `必要` 可摊销。

### 5.3 分类偏差 (Deviation)

```
dev(c) = spent(c, period) − standard(c)        // > 0 为高于标准
```
- 分类标准之和不必等于总标准；差额显示为 `未分配 ¥N`（`N` 可为负，此时显示 `超额分配 ¥N`）。
- 偏差条：0 处一条竖发丝线；`dev < 0` 向左（`--ink-700`），`dev > 0` 向右（`--fig-over`）。条高 6px，宽度按 `|dev| / maxAbsDev` 归一。
- 未设置分类标准的类别不进入偏差图，改列入表格底部 `未设标准` 分组。

### 5.4 待购冷静期 (Cooling-off wishlist)

```
coolDays(price_fen) = clamp(ceil(price_fen / 10000), 1, 14)     // ¥100 → 1 天
unlockAt = createdAt + coolDays × 86400_000  ms
```
- 展示分档（仅文案，计算仍连续）：`1–2 天` / `3–7 天` / `8–14 天`。这样既避免 ¥999 / ¥1,001 的悬崖套利，又便于口头理解。
- 递减弧：`progress = clamp((now − createdAt) / (unlockAt − createdAt), 0, 1)`，逆时针递减，1px 描边，butt cap，`--fig-held`，**每 60 秒重绘一次**。
- 解锁后浮顶，只问 `仍然想要吗？`：
  - `记入账页` → 打开记账面板，金额与名称预填，`intent` 预置为 `想要`（仍需用户确认点击，不算自动填印章），`entry.wantId` 记录来源。
  - `不买了` → 写 `AbstainedWant{ wantId, priceFen, abstainedAt }`。
- `本年已放弃 = Σ AbstainedWant.priceFen（当年）`，`--fig-spared`。
- 待购项 30 天未处理：不删除、不催促，移到列表底部 `久置` 分组，倒计时改显 `已过 N 天`。
- **平台差异（明示）**：iOS 在 `unlockAt` 投递本地通知（`UNUserNotificationCenter`，首次创建待购项时请求权限，拒绝则静默降级）。Web **不投递通知**：Service Worker 在每次启动时检查解锁项，今日屏出现 `待购 2 项已解锁` 行。这是本应用最强机制在 Web 上的真实弱化，已知并接受（§11 R-7）。

### 5.5 印章与后悔评分 (Intent & regret)

```
待判集合 = { e | e.intent ∈ {想要, 冲动}
              ∧ e.reviewedAt == null
              ∧ e.deferrals ≤ 3
              ∧ occurredOn ∈ [审判时刻 − 7 天, 审判时刻) }
卡片排序 = amount desc，取前 12
```
```
月度后悔 = Σ effective(e) where e.worthIt == false ∧ e.occurredOn ∈ period
本年后悔 = Σ effective(e) where e.worthIt == false ∧ e.occurredOn ∈ 自然年
后悔率(c) = 不值笔数(c) / 已判笔数(c)
全局后悔率 = 不值笔数 / 已判笔数
```
- **样本门槛**：全局已判 < 30 笔时，后悔率与方块图不渲染，改印 `已判 12 笔 · 满 30 笔后给出后悔率`。分类后悔率另需该类已判 ≥ 8 笔。
- **稍后（deferral）**：每笔最多 3 次。第 4 次出现时自动写 `worthIt = false`、`autoJudged = true`、`autoReason = "未敢面对"`。这些笔**计入**后悔金额，但在报告中单列一行 `其中未敢面对 ¥238 · 4 笔`。
- 冲动权重：`冲动` 笔在 §4.8 第 3 种按钮文案的触发判定中权重 ×1.5（即 `加权后悔率(c) = (不值必要*0 + 不值想要*1 + 不值冲动*1.5) / (已判想要*1 + 已判冲动*1.5)`）。`必要` 从不进入判决。
- 判决后的记录在账页行末的印章字后追加一个等宽字符：`值` → `·`，`不值` → `×`（`--fig-regret`）。无颜色块、无删除线。

### 5.6 周期性扣费探测 (Recurring detection)

纯本地、纯函数、TS 与 Swift 共用同一份测试向量（§附录 D）。

```
merchantKey(s) = 去空白 → 全角转半角 → 小写 → 去除 [0-9]{4,} 与常见后缀(店/分店/有限公司/#\d+)
分组 g = 同 merchantKey 且 金额落入同一 amountBucket
amountBucket: 两笔金额 a,b 同桶 ⟺ |a − b| ≤ 0.05 × max(a,b)
命中条件：
  n = |g| ≥ 3                      （类别为 餐饮 时 n ≥ 5）
  ∧ stddev(相邻间隔天数) < 4
  ∧ mean(相邻间隔天数) ∈ [6, 400]
推断周期 = argmin_p |mean(间隔) − p| , p ∈ {7, 14, 30, 31, 91, 182, 365}
```
- 命中结果进入 `待认领`，行文案：`网易云音乐 · ¥15 · 近 5 次 · 约每 30 天 · 待认领`。
- 每行三个动作：`保留`（转为正式订阅，计入年化）/ `待退订`（转为订阅并打上 `待退订` 等宽标记，仍计入年化）/ `不是订阅`（写入 180 天抑制名单）。
- **在用户签署前，探测结果绝不计入 `年化` 数字**（AC-13.2）。默认从「它会一直扣」翻转为「你得签个字」。

### 5.7 订阅年化与已付

```
periodsPerYear: 周=52, 月=12, 季=4, 半年=2, 年=1
年化 = amountFen × periodsPerYear
每天 = round(年化 / 365)                       // 四舍五入到分
页首年化 = Σ 所有 active 订阅的年化
已付(确认) = Σ 关联 entry 的 effective 金额
已付(估算) = amountFen × 已发生周期数(自 firstChargedAt 到今天)
每次使用 = 近 90 天费用 / 近 90 天使用次数     // 使用次数 < 3 不显示
近 90 天费用 = amountFen × ceil(90 / 周期天数)
已省(已终止) = floor((today − cancelledAt).days × 年化 / 365)
```
- 已付优先用确认值；无关联 entry 时用估算值并在其后附 ink-300 等宽 `估算`。
- 排序：`年化 desc`，同值按 `已付 desc`。
- 年化分段条：单条水平条，按年化占比分段，段间 1px 发丝线，填充在 `--ink-700` / `--ink-500` 间交替；每段以 1px 引线连到下方排序标签列。占比 < 3% 的段合并为末段 `其他 N 项`。

### 5.8 小额漏水 (Leak aggregation)

```
漏水笔 = { e | effective(e) < leakCeiling }        // leakCeiling 默认 3000 分
本月漏水笔数 = |漏水笔 ∩ period|
本月漏水金额 = Σ effective
大额中位数 M = median{ effective(e) | e ∈ 近 90 天 ∧ effective(e) ≥ leakCeiling }
等价大额次数 = round(本月漏水金额 / M, 1)          // 一位小数
```
- `|{ e ≥ leakCeiling ∧ 近 90 天 }| < 10` 时不显示 `≈` 从句。
- 商户维度重述（报告页，取频次前 3）：`便利店 ×14 · ¥382 · 近 30 天 · ≈ 2.6 次大额支出`。

### 5.9 月度评级（取代打卡连续天数）

**决定：本应用没有连续打卡（streak）。** 连续天数制造「为保连胜而不记账」的反向激励，且语气与本应用不符。取而代之的是每月独立可赢的评级，公式在设置页原文公开：

```
完整度 C = 已记录天数 / 周期内已过天数
           （一天算已记录 ⟺ 有 ≥1 条记录 或 有一次「今天没花钱」打卡）
达标度 S = clamp(1 − max(0, 实际支出 − 月度标准) / 月度标准, 0, 1)
履行度 R = 已判笔数 / 应判笔数     （应判 = 超过 24 小时的 想要+冲动 笔；应判为 0 时 R = 1）

评分 = 0.40 × C + 0.35 × S + 0.25 × R
评级：≥0.90 A · ≥0.80 B · ≥0.70 C · ≥0.60 D · 其余 E
```
- 呈现：报告页一个等宽大写字母 + 三行分解 `完整度 0.93 · 达标度 0.81 · 履行度 1.00`。**无颜色、无徽章、无动画、无历史评级曲线。**
- 每月独立计算，坏月份不影响下月，从而不触发「已经毁了，索性不记了」。

### 5.10 结账与更正 (Period close)

- 周期滚动到下一个 `periodStartDay` 的 00:00（按日切）时，上一周期被封存：写入 `PeriodClose{ periodId, closedAt, totalFen, standardFen }`。
- 封存后：
  - 记录不可原地修改。编辑 → 追加 `Correction{ entryId, prevFen, newFen, reason(≥2字), at }`。
  - 删除 → 追加 `Reversal{ entryId, reason(≥2字), at }`，`effective = 0`。
  - 新增补录 → 允许，但强制附事由，并在账页标记 `补录`。
- 聚合一律按更正后的 `effective` 重算；更正行与冲销行**永久可见**，不可删除、不可折叠隐藏。
- 当前周期内的编辑与删除自由且无痕（删除有 8 秒 `撤销`）。
- 跨设备强制：任何针对已封存周期记录的 `entry_update` / `entry_delete` 事件在收敛时被丢弃并转换为对应的 `correction` / `reversal` 事件（§8.5 归并规则）。

### 5.11 周期对比

```
环比 Δ(c) = spent(c, 本周期) − spent(c, 上周期)
同比 Δ(c) = spent(c, 本周期) − spent(c, 去年同周期)
```
- **只在双方基数 ≥ ¥100 时给出百分比**；否则只给绝对差额并标 `基数过小`。
- 对比同样以偏差语言表达：主图是本周期对标准的偏差，环比/同比是表格中的两列，不额外画图。

### 5.12 破版 (Margin break)

- 触发：`spentToday > dailyAllowance`（即 `todayAvailable < 0`）。
- 表现：今日屏英雄数字下方的规则线，以及月度日柱的基线，右端越出 720px 内容列 **20px**，仅被安全区裁切。
- 实现：Web `margin-right: -20px`（父级不得 `overflow: hidden`）；SwiftUI `.padding(.trailing, -20)`。
- 月度日柱中，超过标准线的柱段用 45° 斜纹（SVG `<pattern>` / SwiftUI 重复 `Path`）而非第四种颜色，斜线宽 1px、间距 3px、色 `--ink-500`。

### 6.2 预算模型（标准）

- **月度标准**（`standardFen`，必填）：一个数字，代表「我认为一个正常月份的总支出上限」。它是**支出标准**，不是收入，也不是储蓄目标。
- **分类标准**（可选，每类一个数字）：`Σ 分类标准` 与 `月度标准` 无需相等；差额展示为 `未分配 ¥N` / `超额分配 ¥N`。
- **固定支出**：两个来源 —— (a) 已认领订阅的预计扣费；(b) 用户手工登记的固定支出（名称 + 金额 + 每月第 N 天）。二者共同构成 §5.2 的 `fixedRemain`。
- **建议值**：数据满 30 天后，每个字段旁以 `--ink-300` 显示 `近 90 天中位数 ¥6,240`，旁附文本链接 `采用`。**绝不自动写入。**
- **修改留痕**：任何标准/阈值修改写入 `StandardRevision{ field, from, to, at }`，在报告页脚按日期列出，永不清除。
- **不做的事**：不做信封预算（envelope）、不做结转（rollover carry-over 跨月）、不做多账户/多钱包、不记收入、不算净资产。理由见 §9。

### 7.6 文案宪法（全局强制，评审项）

1. 只陈述，不评价。禁止出现：太多、超支了、注意、小心、加油、真棒、继续保持、你做得很好。
2. 禁止感叹号、禁止表情符号、禁止拟人化第一人称（「我帮你…」）。
3. 禁止「相比上月你进步了」之类的软化句附着在 `本年后悔` 上。
4. 负号一律 U+2212 `−`，不用连字符，不用括号表示负数。
5. 空状态是陈述事实而非鼓励：`本月还没有记录` / `没有待购项` / `没有已终止的订阅`。
6. 英文文案遵循同一宪法，且不做中文的逐字直译（见 §8.3）。

## 8. 设置、货币、语言、数据

### 8.1 外观

- `跟随系统 / 浅色 / 深色`（默认跟随系统）。
- `高对比度`（默认关）：切换到备用 token 集，`--rule` 提升到与 `--surface` 至少 3:1（浅 `#C9C5BB` → `#9A968C`，深 `#2B2A27` → `#55534E`），发丝线宽度固定 1px（不降到 0.5px）。
- `减弱动效` 跟随系统 `prefers-reduced-motion` / `accessibilityReduceMotion`，另提供应用内强制开关。
- 字号：iOS 支持 Dynamic Type（全部字号以 `.custom(size:relativeTo:)` 绑定语义样式）；Web 以 `rem` 为单位，根 `font-size: 100%`，用户浏览器字号设置生效；应用内另提供 `标准 / 大 / 更大` 三档（对应根 16 / 18 / 20px），比例关系（64/44/34/17/15/11/10）保持不变。

### 8.2 货币

- 默认 `CNY`，符号 `¥`，minor unit exponent = 2。
- 可切换显示符号与代码（`¥ / $ / € / £ / HK$ / NT$ / ₩ / ¥JPY`）。`JPY / KRW` 的 exponent = 0，此时键盘的 `.` 键禁用、金额三段式省略分部。
- **不做汇率换算、不做多币种账本**（§9 N-8）。一个账本一种货币；切换货币只改变符号与小数位，**不换算历史金额**，并在切换时写入一条 `StandardRevision` 与一行报告页脚说明。

### 8.3 语言

- `zh-CN`（默认）与 `en`。启动时按系统语言选择，用户可覆盖。
- 字符串以两份独立 JSON 维护（`zh-CN.json` / `en.json`），键名英文语义化。英文不是中文直译：`据实` 的英文界面用 `Available today`、`Necessary / Wanted / Impulse`、`Worth it / Not worth it`、`Regret this year`、`Given up`、`Cooling`、`Closed`、`Correction` / `Reversal`。
- 日期格式：zh `2026-03-14 周五`；en `Fri, 14 Mar 2026`。两端均使用 ISO 数字月日于紧凑处（`03-14`）。
- 数字分组：两语言均 `1,238.40`（中文环境不使用「万」为单位分组）。**决定：不引入「万」**——它会破坏等宽数字列的对齐，且降低金额的具体性。

### 8.4 阈值与标准（设置项已在 §6.2 / §6.3 定义）

设置页额外展示两块只读内容：
- **印章释义**（§4.5 的三条定义原文）。
- **评级公式**（§5.9 的公式原文，含权重与分档），以等宽排版。

### 8.5 多端登录与同步

**账本模型**：一个账本 = `bookId`（16 字节随机，显示为 32 位大写十六进制）+ `passphrase`（用户设定，≥ 10 字符，界面提示可用中文短句）。没有邮箱、没有手机号、没有第三方登录、没有密码找回（明示：**口令丢失即数据不可解密**，首次设置时需勾选确认）。

**密钥派生与加密**
```
masterKey  = PBKDF2-HMAC-SHA256(passphrase, salt = bookId, iterations = 310000, dkLen = 32)
dataKey    = HKDF-SHA256(masterKey, info = "countbook/data/v1", len = 32)
authKey    = HKDF-SHA256(masterKey, info = "countbook/auth/v1", len = 32)
fingerprint= SHA-256(authKey)[0..7]  → 四组四位大写十六进制  4F2A · 91C7 · 0B3E · D845
密文       = AES-256-GCM(dataKey, nonce = 12 随机字节, plaintext = 事件 JSON)
```
- Web：WebCrypto (`deriveBits` PBKDF2 / `HKDF` / `AES-GCM`)。iOS：PBKDF2 用 `CommonCrypto`（系统框架，非第三方），HKDF 与 AES-GCM 用 `CryptoKit`。
- 服务器只见 `bookId`、`HMAC(authKey, bookId)` 作为凭据、以及不透明密文块。**服务器永不接触明文与密钥。**

**同步协议**（单端点 HTTP，可自建，Caddy 反代）
```
POST /v1/push   { bookId, auth, events: [ { id, hlc, ciphertext, nonce } ] }  → { accepted, serverSeq }
GET  /v1/pull?bookId=…&since=<serverSeq>&auth=…                              → { events: [...], serverSeq }
```
- 传输幂等：`event.id` 为 ULID，服务端与客户端均按 id 去重。
- 触发时机：启动、前台恢复、写入后 2 秒防抖、手动下拉。失败静默重试（指数退避 2/4/8/16/32s，上限 5 分钟），**永不弹错误**；状态词变为 `待同步`。

**事件日志与归并**
- 全应用状态由**只追加**的事件日志派生。事件类型：`entry_create` `entry_update` `entry_delete` `correction` `reversal` `verdict` `defer` `want_create` `want_abstain` `want_convert` `sub_create` `sub_update` `sub_cancel` `sub_usage` `sub_claim` `standard_revise` `zero_day_mark` `zero_day_void` `wish_set` `amortize` `period_close` `settings_set`。
- 每条事件带混合逻辑时钟 `hlc = "<millis>:<counter>:<deviceId>"`，比较顺序为 millis → counter → deviceId 字典序。
- 归并：同一实体同一字段，**HLC 最大者胜**（LWW）；`correction` / `reversal` / `verdict` 为追加型，永不被覆盖。
- **结账强制**：收敛时若某 `entry_update` / `entry_delete` 的目标 `occurredOn` 落在已存在 `period_close` 的周期内，且该事件的 HLC 晚于 `period_close`，则该事件被转换为等价的 `correction` / `reversal`（事由填 `跨设备修改`）。这使 §5.10 的不可变性在多端下真正成立。
- 冲突可见性：不做冲突提示 UI。多端同时编辑同一笔的结果是「后写的赢」，且在已结账周期内会留下更正行——这本身就是记录。

**设备列表**：每设备一条 `Device{ deviceId, name, lastSyncAt }`，名称默认取系统设备名，可改。可 `移除设备`（写入 `device_revoke`，该设备下次同步被拒并本地提示 `此设备已被移除`，本地数据保留但转为只读导出态）。

**决定：不使用 iCloud / CloudKit。** 理由：Web 端无法读取，会造成两端数据不通，违反「多端可登录」的核心承诺。两端一律走同一 HTTP 中继协议。

**离线优先**：同步关闭或不可达时，全部功能完整可用；同步只影响多设备一致性，不影响任何单机功能（评审项）。

### 8.6 导出与导入

**CSV 导出**（UTF-8 with BOM，`\r\n`，字段含逗号时用双引号包裹）
```
date,time,category,category_en,intent,amount_yuan,amount_fen,note,reason,merchant,verdict,auto_judged,amortized,corrected,void,entry_id
2026-03-14,19:42,餐饮,Dining,冲动,68.00,6800,"和同事吃饭","换来一顿不用做饭的晚上",海底捞,不值,false,false,false,false,01HW...
```
- 另导出 `wants.csv` `subscriptions.csv` `standards.csv`（标准修订）四个文件，打包为 `countbook-export-YYYYMMDD.zip`（Web 用手写的 store-only zip 打包器，零依赖；iOS 用 `Foundation` 的 `FileManager` + 手写 zip 写入器）。若打包不可用则逐个文件保存。

**JSON 导出**（完整 bundle，可完全还原）
```json
{
  "app": "countbook",
  "schemaVersion": 1,
  "exportedAt": "2026-03-14T11:42:03Z",
  "bookId": "9F3C…",
  "currency": { "code": "CNY", "symbol": "¥", "exponent": 2 },
  "settings": { … },
  "events": [ { "id": "01HW…", "hlc": "…", "type": "entry_create", "payload": { … } } ]
}
```
- **导出的是事件日志**，不是快照——这保证导入后更正、冲销、判决的全部历史一字不差地还原。
- 导入语义为**合并**：按 `event.id` 去重，按 HLC 归并。导入前显示 `将新增 {412} 条 · 跳过 {96} 条`，需确认。
- **不支持 CSV 导入**（§9 N-9）：CSV 缺少 intent 与事件因果，导入后会产生 intent 为空的记录，直接违反 AC-1.4。

**本地占用**：设置页以等宽显示 `本地数据 1.84 MB · 事件 12,406 条 · 快照 03-14 20:41`。

**清除本地数据**：需输入 `清除` 二字确认；若同步开启，明示 `云端副本不会被删除`。

## 10. 附录 A：数据模型（规范）

金额一律 `Int64` 分。id 一律 ULID（26 字符，字典序即时间序）。

```ts
type Intent = 0 | 1 | 2            // 0=必要 1=想要 2=冲动

interface Entry {
  id: string                        // ULID
  ts: number                        // 写入时刻 epoch ms
  occurredOn: string                // "YYYY-MM-DD" 记账日（按日切）
  amountFen: number                 // > 0
  categoryId: string
  intent: Intent                    // NOT NULL, NO DEFAULT
  note?: string                     // ≤ 40
  reason?: string                   // ≤ 20 「写给未来的自己」
  merchant?: string                 // 用户输入的商户名（可空）
  merchantKey?: string              // 归一化，探测用
  amortized: boolean                // 大额必要摊销
  backfilled: boolean               // 非当日补录
  wantId?: string                   // 来自待购
  subscriptionId?: string           // 订阅扣费的实际记录
  reviewedAt?: number
  worthIt?: boolean
  autoJudged: boolean
  autoReason?: "未敢面对"
  deferrals: number                 // 0..3
}

interface Correction { id; entryId; prevFen; newFen; reason: string /* ≥2 */; at: number }
interface Reversal   { id; entryId; reason: string /* ≥2 */; at: number }

interface Want {
  id; name: string /* ≤20 */; priceFen: number; createdAt: number
  unlockAt: number                  // = createdAt + coolDays*86400000
  state: "cooling" | "unlocked" | "bought" | "abstained" | "stale"
  boughtEntryId?: string; abstainedAt?: number
}

interface Subscription {
  id; name: string; amountFen: number
  period: "week"|"month"|"quarter"|"half"|"year"
  anchorDay: number                 // 1..28 或 1..7(week)
  firstChargedAt: string            // "YYYY-MM"
  claimed: "unclaimed"|"kept"|"toCancel"
  cancelledAt?: number
  autoEntry: boolean                // 是否自动生成 entry
  detectedFrom?: { merchantKey: string; sampleIds: string[] }
}
interface SubscriptionUsage { id; subscriptionId; at: number }

interface Standard { periodId: string; totalFen: number; byCategory: Record<string, number> }
interface StandardRevision { id; field: string; from: string; to: string; at: number }
interface PeriodClose { periodId: string; closedAt: number; totalFen: number; standardFen: number }
interface ZeroDayMark { id; day: string; at: number; voided: boolean }
interface WishItem { id; name: string /* ≤12 */; priceFen: number }
interface Device { deviceId: string; name: string; lastSyncAt?: number; revoked: boolean }

interface Event { id: string; deviceId: string; hlc: string; type: string; payload: unknown }
```

**持久化**
- Web：IndexedDB 数据库 `countbook`，object stores `events`（主键 id，索引 hlc）、`snapshot`（单条物化视图）、`meta`。每 500 条事件写一次快照。
- iOS：`Application Support/countbook/events.ndjson`（只追加，每行一个事件 JSON）+ `snapshot.json`（每 500 条事件重写）。启动时读快照 + 重放尾部事件。无 SQLite、无 Core Data、无第三方。

## 11. 附录 B：跨端设计系统契约（实现强制项）

### B.1 单一 token 源
`design/tokens.json` 是仓库中唯一存在颜色十六进制值、圆角、间距、图表几何常量的文件。构建期生成两份产物：

CI 断言：`grep -rE '#[0-9a-fA-F]{6}'` 在 `tokens.json` 与生成产物之外**零命中**。

### B.2 三色三义 + 一个非色
| Token | 浅色 | 深色 | **唯一用途** |
|---|---|---|---|
| `--fig-over` 红氧化 | `#A32A22` | `#E0655A` | (1) 为负的 `今日可用`；(2) 偏差图中高于标准的条与数字；(3) 本地写入失败一行 |
| `--fig-held` 暗黄铜 | `#8A6A1F` | `#D2A64A` | 冷静期中的项、`挂起 N 天` 按钮、`待同步` |
| `--fig-spared` 深松绿 | `#2E5D4B` | `#6FA98A` | `已放弃` 与 `已省` 总额 |
| `--fig-regret` 冷铅灰 | `#4A4C4E` | `#8B8E91` | `本月后悔` / `本年后悔` / 后悔率方块中的「不值」/ 账页中的 `×` |

`--fig-regret` 是**冷中性色**（与暖墨色阶可辨），语义是「未获颜色」：后悔从不配得墨色。它不计入「三色」，但同样受「每屏至多一个数字」的约束。
基础色阶（浅/深）：`--paper #F7F6F3 / #121211`、`--surface #FFFFFF / #1A1A18`、`--surface-sunken #F1EFEA / #0E0E0D`、`--ink-900 #111110 / #F2F0EA`、`--ink-700 #35342F / #C9C6BE`、`--ink-500 #6E6C64 / #8C897F`、`--ink-300 #A5A29A / #605D56`、`--rule #E2DFD8 / #2B2A27`、`--rule-strong #C9C5BB / #3D3B36`。

三段式 `¥ / 元 / 分` 排版**只允许存在于这一个组件**（Web）与这一个 View（iOS）中。CI 断言：`.fig` class 与 `MoneyText` 之外不出现 `0.56em` / `0.44em` 字号。

### B.5 共享几何模块
`shared/geometry/*.json` 定义常量（柱宽 3、间距 2、条高 6、弧线宽 1…）；`shared/geometry/*.spec.json` 是测试向量：给定输入数组，TS 与 Swift 的纯函数必须输出**逐位相同**的归一化坐标数组。六种图表 + 时段散点全部走此模块。CI 同时跑 TS 与 Swift 两套断言。

### B.6 排版与动效
- 字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "Helvetica Neue", system-ui, "Segoe UI Variable", "Segoe UI", Roboto, sans-serif, "PingFang SC", "HarmonyOS Sans SC", "Source Han Sans SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`；等宽：`ui-monospace, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace`。零 Web 字体。
- 非 Apple 平台补偿（R-3）：检测到回落到 `Microsoft YaHei` 时，通过 `@font-face` 无法解决——改为应用 `[data-cjk="fallback"]` 覆盖：字重整体降一级（300→400 的英雄数字改为 300 保持，但正文 400→400、label 600→500）、字距 `letter-spacing` 减 0.01em、发丝线宽固定 1px。检测方式：离屏测量 `PingFang SC` 与 `sans-serif` 的字宽差。
- 唯一缓动 `cubic-bezier(0.32,0.08,0.24,1)`。唯一阴影（仅面板与模态）：`0 1px 2px rgba(17,17,16,.04), 0 12px 32px -8px rgba(17,17,16,.16)`。遮罩 `rgba(17,17,16,.28)`，无模糊。
- 发丝线：Web `border-width:1px`，`@media (min-resolution:2dppx){ border-width:.5px }`，`[data-contrast="high"]` 下强制 1px；iOS `1/UIScreen.main.scale`，高对比下为 1pt。
