# 据实 · Countbook — 屏幕规格 / Screen-by-Screen UI Spec

> 这个应用从不说"你花太多了"。它只说「今日可用 −¥84.20」，然后让这个数字待在那里。
> *This app never says "you spent too much." It says 今日可用 −¥84.20, and lets that sit there.*

## 0. 如何阅读本文档 / How to read this

1. **分工。** `DESIGN.md` 规定*长什么样*（令牌、组件、动效、图表几何）；本文档规定*屏幕上有什么、按什么顺序、说什么话、点了会怎样*。两者冲突时以 `DESIGN.md` 为准，并回来修正本文档。
2. **每个屏幕**给出：一行目的 → ASCII 线框（手机宽；Web 宽屏若有实质差异则附第二张）→ 自上而下的逐元素表（内容 · 令牌 · 中英文案键 · 行为）→ 载入/空/错误态 → 进出转场。
3. **线框约定**：只画上下边界与左边框——中文在等宽渲染下是双宽字符，右边框永远对不齐，画了就是噪声。`▁▂▃` 柱形，`▬` 水平条，`·` 发丝线，`▮` 实心墨块，`◠` 冷静弧，`( )` 可点热区，`[ ]` 满宽按钮条，`›` 展开箭头（`chevron.right`，`DESIGN.md` §8.3 #1）。
4. **令牌名**一律取自 `DESIGN.md`：`--ink-900`、`--t-fig-hero`、`--s-5`、`--fig-regret` 等。本文档中出现的任何数值都是**引用**，不是来源；十六进制与几何常量只存在于 `design/tokens.json` 与 `tokens/geometry.json`。
5. **文案键**（`today.hero.label`）来自第 16 节文案册，是 i18n 唯一真值。线框与元素表里出现的每一句中文都必须能在文案册中按键找到。
6. **金额**一律写成最终渲染形态 `¥1,238.40`（`<Money>` 组件，`DESIGN.md` §3.6：`¥` 0.44× `--ink-300`／整数 1.00× 角色色／`.40` 0.56× `--ink-300` 固定 2.6ch 前进宽度）。负号一律 U+2212 `−`，从不用括号、从不用连字符。任何屏幕代码里手写 `¥` 都是评审必须打回的错误。

## 1. 全局构件 / Global chrome

### 1.1 导航

| 断点 | 形态 |
| --- | --- |
| < 720px（手机 / 窄网页 / iOS compact） | 底部标签栏，高 `--tabbar-h` 49 + 安全区，顶边 `.rule--critical` 发丝线。五个**文字**：`今日 · 账页 · 报告 · 待购 · 设置`。选中态：`--ink-900` 600 字重 + 顶边 2px `--rule-stamp` 指示条（随 `stampSlide` 滑动）。**无图标、无填充、无角标。** |
| ≥ 720px（宽网页） | 顶部导航条，高 52，`--paper` 底，同样五个词，`--t-label`，左对齐，间隔 `--s-6`，活动词下 2px `--rule-stamp`；下方一条贯穿视口的 `.rule--critical`。**不渲染底部标签栏。** 内容仍是单列 `--content-max` 720 居中，`--gutter` 由 20 变 32——**720 以上只是纸更多，不分栏。** |

`订阅` 不占标签位：入口在 `报告` 页与 `设置` 页各一处，作为 push 屏出现。

### 1.2 `记` 按钮（`DESIGN.md` §5.13）

56 直径 `--ink-900` 圆，内含 `记`（22/500，`--paper`），**不是加号**，无阴影。位置：距右 `--gutter`，距标签栏顶 16。出现在 `今日` 与 `账页` 两屏；`报告`、`待购`、`设置` 不出现（那些页面上你不该在记账）。长按 500ms → 打开面板并置"连续记账"。

### 1.3 状态态的总原则

| 类型 | 规则 |
| --- | --- |
| **载入** | 本地优先，账本来自 IndexedDB / SQLite，首屏预算 120ms。**禁止骨架屏、禁止转圈**（全应用没有任何 spinner，`DESIGN.md` §8.4）。若 120ms 内无数据，在内容位置显示一行 `--t-label` `--ink-300` `common.loading`；超 3s 转错误态。 |
| **空** | 一句陈述 + 至多一个文字链接，距内容区顶 `--s-9`（56），**不垂直居中**。无插画、无图标、无大字符。图表的空态占用图表原高度，数据到达时页面不重排（`DESIGN.md` §5.11 / §7.8）。 |
| **错误** | 一行事实描述 `--t-body` `--ink-700`，左侧 2px `--ink-900` 竖线 + `exclamationmark` 图标（`DESIGN.md` §8.3 #14），后跟一个文字链接动作。**错误不用红色**——红被配给了三处用途，报错不在其中。不用弹窗，不用 toast。 |
| **样本不足** | 不画图，改印诚实的差额计数（§7.8 表）。 |
| **Toast** | 全应用只有两种：删除后的 `撤销`，与长按提交的"已存入 · 继续记"确认。4,000ms，无进度条。 |

### 1.4 派生量的权威定义（实现只写一次）

```
daysRemaining      = daysInMonth − dayOfMonth + 1                  // 含今天
pool_fen           = standard_fen − spentBeforeToday_fen − fixedRemaining_fen
dailyAllowance_fen = floorDiv(pool_fen, daysRemaining)             // 余数推到最后一天
todayAvailable_fen = dailyAllowance_fen − spentToday_fen           // 今日可用，可为负
dayStandard_fen    = floorDiv(standard_fen, daysInMonth)           // 月度日柱的标准线
coolingDays        = clamp(ceil(price_fen / 10000), 1, 14)         // ¥100→1 天，¥1,400→14 天
leakEquivalent     = leakSum_fen / median90(entries > leakCeiling) // 需 ≥20 个大额样本
regretRate(cat)    = count(worthIt == false) / count(reviewedAt != nil)
regretYear_fen     = Σ amount where worthIt == false and year(entry) == y   // 永不重置
```

> **今日可用当天是全额减法。** 花掉 ¥68，数字掉 ¥68，不是 ¥68 ÷ 18。跨天才重新摊平。这样"多花的 ¥400"与记账动作在同一拍到达，而不是被摊薄成一个感觉不到的数。

**全文档统一示例数据**（各屏线框互相自洽）：2026-03-14（周六），月度标准 ¥8,000.00，本月今日之前已花 ¥5,112.80，固定待扣 ¥612.00，剩余 18 天 → `dailyAllowance = ¥126.40`；`dayStandard = ¥258.06`。

## 2. 屏幕地图与转场 / Screen map & transitions

```
今日 ──(记)──▶ 记一笔面板 ──保存──▶ 回到来处 + rowPrint + figureSettle
 │  ├─小额漏水──▶ 账页（预置筛选）
 │  ├─日柱点选──▶ 账页（定位该日）
 │  └─待判入口──▶ 周日审判（全屏模态）──完成──▶ 今日
账页 ──行──▶ 单笔详情 ──更正/冲销──▶ 账页 + rowPrint
报告 ──▶ 订阅 ／ 账页（筛选）／ 标准线
待购 ──(＋)──▶ 加入待购面板；解锁项 ──记入账页──▶ 记一笔面板（预填）
设置 ──▶ 标准线 ／ 心愿物 ／ 订阅 ／ 设备与同步 ／ 数据
首次运行 ──▶ 初次设置 1/3 → 2/3 → 3/3 ──▶ 今日
```

| 转场 | 规格 |
| --- | --- |
| 标签之间 | **瞬时切换**，无位移、无淡入。标签之间没有空间关系，动画是戏剧。 |
| push / pop（详情、订阅、标准线、设备） | iOS 平台默认 push/pop；Web 为瞬时替换（浏览器返回可用）。 |
| 面板（记一笔、加入待购） | `sheetPresent` 280ms + `scrimFade` 200ms；退出 `sheetDismiss` 200ms。 |
| 全屏模态（周日审判、初次设置） | translateY 24 → 0 + 淡入 280ms；退出 200ms。 |
| 保存一笔 | 签名时刻，见 §4.7（`DESIGN.md` §6.5 为规范来源）。 |
| 减少动效 | 全部塌缩为 100ms opacity；`holdRing` 的 3,000ms 不变（延迟是机制，动画只是它的外观）。 |

## 4. 记一笔 Capture sheet（Quick Entry）

**目的**：6 秒内记完一笔，同时强制**恰好一次**自我归类。

> **这是全产品的承重路径。** 记账中位耗时一旦持续超过 8 秒，完整性开始崩塌，而所有机制都依赖完整数据。因此本屏**永远只有一个必填的新字段（印章）**；第二个必填项只在一个极窄条件下出现（§4.5 C6），并被设置页的自我度量持续监视。

### 4.1 线框 · 手机（默认）

```
┌───────────────────── 面板 480 宽 · --r-sheet 顶角 ─┐
│                                        连续记账 ○ │ ← --t-label（无标题栏、无把手、无关闭按钮）
│
│                                          ¥68.00  │ ← --t-fig-screen，右对齐，1px 光标
```

## 17. 实现清单 / Build checklist

1. **令牌**：`design/tokens.json` → `web/src/styles/tokens.css` + `ios/Countbook/Design/Tokens.swift`。屏幕代码里不得出现任何十六进制、间距数字或时长。
2. **几何**：`packages/geometry`（TS）与 `ios/Countbook/Design/Geometry.swift`（Swift）实现同名纯函数，由 `tokens/fixtures/geometry/*.json` 同一批测试向量双向验证。七种图表全部走它。
3. **`<Money>` / `MoneyText`**：全应用唯一金额渲染点，`aria-label` / `accessibilityLabel` 在此一处烘焙。任何别处的 `¥` 拼接都是评审阻断项。
4. **记账中位耗时埋点**（本地，不上传），显示在设置页 G8——第一号风险的仪表。
5. **结账任务**：每月 1 日 00:00 本地封存上月；跨设备一致性由 HLC 事件日志保证，不需要额外同步逻辑。
6. **常量集中**：冷静期起点 ¥300、漏水上限 ¥30、冷静天数 `clamp(ceil(fen/10000),1,14)`、审判 12 张上限、稍后上限 3 次、后悔率门槛 30 笔、偏差条 14 天、时段散点 40 笔、订阅识别 ≥3 次（餐饮 ≥5）——全部只出现在 `design/tokens.json` 的 `rule` 块。
7. **文案**：第 16 节导出为 `web/src/i18n/{zh-CN,en}.json` 与 `ios/Countbook/Resources/Localizable.xcstrings`，键一致；缺键在开发构建下报错而不是回退。
